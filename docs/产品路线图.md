# 灵阅产品路线图

> 文档状态：M1-A/M1-C 已完成实现和 Pixel_9 验收；M1-B 实现完成，尚需补充 10 MB 以上文件的明确设备验收记录；M2 Markdown 主要切片已随 `v0.1.18` 发布；M3 安全轻量编辑与 M4 更新预览/修改保护已随 `v0.1.19` 发布，冲突文件只读查看随 `v0.1.20` 发布；新增文件入口随 `v0.1.22` 发布，类型化模板创建随 `v0.1.23` 发布；新增文件弹窗体验优化随 `v0.1.24` 发布；Pixel_9 最近一次全量 91/91 通过  
> 更新时间：2026-08-16（北京时间）  
> 当前版本基线：`v0.1.24`

## 1. 产品定位

灵阅是一款面向开发者的 Android 通用源代码阅读与轻量编辑工具。

核心场景是：在手机上稳定打开主流编程语言项目和 Markdown 文档，快速浏览目录、搜索内容、定位代码，并在需要时进行小范围修改。

产品优先级为：

1. 源码阅读可靠性
2. 项目和文件导航效率
3. Markdown 高级文档阅读
4. 轻量编辑
5. Git 和项目管理

灵阅不以移动端完整 IDE 为目标，不承担编译、调试、运行项目和完整 LSP 开发环境的职责。

## 2. 当前能力基线

### 2.1 已实现能力

- 支持 `ACTION_VIEW`、`ACTION_EDIT`、`ACTION_SEND` 外部文件入口。
- 支持 SAF 单文件、SAF 目录、ZIP 导入、公共 HTTPS Git 仓库和内置示例。
- 目录、ZIP、Git 和本地项目使用统一的项目索引和可折叠目录树。
- 支持最近项目、项目全局搜索、文件内搜索、搜索命中高亮和快速文件切换。
- 支持多文件标签页，每个标签页独立保存草稿、编辑状态和 Markdown 预览状态。
- 使用 Sora Editor 和 TextMate 实现源码编辑、行号、语法高亮、跳转到行和自动换行。
- 源码编辑模式支持撤销、重做、当前替换、全部替换和正则捕获组替换；全部替换作为一个批次提交，可一次撤销。
- 编辑器输入辅助支持自动缩进、常见块起始符回退、括号与引号补全、2/4/8 Tab 宽度、空格/Tab 缩进方式和多行粘贴缩进优化，设置会实时应用到当前标签。
- 阅读页提供紧凑“编辑操作”面板，支持选中当前行、删除行、复制、剪切、粘贴、缩进和反缩进；只读源码保留选中与复制，其余操作明确禁用。
- 未保存草稿使用应用私有文件自动保存，进程重建后重新打开文件可恢复；原文件变化时会先显示冲突选择，不静默套用旧草稿。
- 本地文件使用同目录临时文件、`fsync` 和原子重命名替换；SAF 写入前备份原始字节，失败时自动回滚并区分“已恢复”和“原文件可能受影响”。
- 不可写来源和分段大文件在阅读页提供“导出原文件副本”；重新读取来源完整原始字节，保留编码、BOM 与换行，显示进度并支持取消，失败或取消时尝试删除系统新建的半成品。
- 当前有约 78 种文件类型映射，覆盖主流语言、脚本、配置和工程文件；其中 73 个带独立 grammar 的类型纳入语义 token 回归。
- Markdown 支持源码/预览切换与语义块位置同步、YAML Front Matter 折叠、本地图片与相对附件、图片放大、表格、任务列表、脚注、代码块高亮、KaTeX 数学公式、Mermaid 流程图、固定可折叠目录和代码复制。
- 大文件阈值和整文件读取上限会按设备内存预算动态决策；大文件进入分段只读模式，Git 克隆和更新提供阶段反馈、进度和取消入口。
- Git 更新先 `fetch` 并展示分支、提交与文件变化范围；工作区修改、未跟踪文件、冲突状态和编辑器未保存草稿会明确列出并阻止更新，确认时再次核对分支、上游、HEAD 与目标提交后仅允许精确快进。
- 支持字号、阅读背景、应用配色、明暗主题和在线更新。

### 2.2 当前明确边界

- 已支持 UTF-8、UTF-8 BOM、UTF-16、GB18030/GBK、Big5、Latin-1 自动识别和手动切换；后续仍需增加编码置信度提示及项目级默认编码。
- 大文件阈值会按设备内存动态落在 512 KB—1 MB，进入分段模式后不能编辑和覆盖保存；整文件读取预算动态落在 8—20 MB。
- 项目全局搜索按编码流式扫描文件全文，不再跳过大于 2 MB 的源码；每个文件最多返回 8 个命中，全局最多返回 200 条。
- Git 当前仅支持公开 HTTPS 仓库、浅克隆、更新预览、修改保护和精确安全快进；不支持 SSH、Token、私有仓库、分支/Tag/Commit 浏览、完整行级 Diff 和冲突查看/处理。
- Markdown 预览使用 APK 内置离线资源，网络加载被禁用；本地图片和附件只能访问当前项目索引内的相对路径，外部资源继续禁止加载。
- 编辑器已具备撤销/重做、查找替换、输入辅助、常用行与剪贴板操作、跨进程草稿恢复、安全保存和不可写来源/大文件完整副本导出；撤销栈不跨标签保留。
- 首页一级操作区提供醒目的“新增文件”入口；Local、应用内导入 ZIP、已克隆 Git 工作区和可写 SAF 目录都按底层写权限决定是否显示。创建前可选择常用源码、配置或 Markdown 类型，系统会生成匹配扩展名、MIME 和最小代码骨架；文件名会做空白、路径分隔符、控制字符、长度和重复文件校验，创建成功后刷新索引并立即进入编辑页；没有可写项目时先选择目录。

### 2.3 综合审计结论

- 当前架构与产品定位匹配，无需推倒重来：Compose 承载产品界面和数据源管理，Sora Editor 负责普通源码阅读，WebView 只负责 Markdown 高级渲染。
- 当前主要短板不是“语言数量不够”，而是 Git 高级生命周期仍需要补齐；M1 阅读主链路只保留 10 MB 以上文件的验收补证。
- 产品已经完成“打开、阅读、导航、搜索、继续阅读”的首轮主链路、M2 Markdown 阅读和 M3 安全轻量编辑；M4 Git 生命周期已进入分步实施，之后再投入符号大纲、结构化视图等差异化能力。
- 不将完整 IDE、LSP、编译、调试和运行环境纳入近期范围，避免功能膨胀影响移动端的打开速度和阅读体验。

### 2.5 产品审计结论摘要

本次审计的核心结论是：灵阅应先成为“可靠、快速、可持续阅读源码和 Markdown 的移动阅读器”，再逐步增加编辑、Git 和结构化能力。功能数量不是第一目标，打开速度、阅读位置、搜索精度、离线可用性和失败恢复才是长期体验的基础。

按用户价值和实现风险，结论收敛为四条执行原则：

1. **先打通阅读主链路（P0）**：来源统一、编码可靠、大文件可读、项目索引完整、文件内/项目搜索可定位、切换后能继续上次阅读。
2. **再补齐 Markdown 和轻量编辑（P1）**：本地资源、预览缓存、源码/预览同步，以及可撤销、可恢复的小范围修改。
3. **最后扩展 Git 和开发者增强（P2）**：认证、分支、Diff、冲突、符号大纲和结构化视图都应建立在稳定阅读内核之上。
4. **质量能力横向贯穿**：统一弹层和导航、紧凑信息密度、无障碍语义、性能观测、隐私与缓存治理，以及仅使用 Pixel_9 模拟器的回归门禁。

审计中明确不把灵阅做成移动端完整 IDE：编译、调试、运行、完整 LSP 和复杂重构不进入近期路线，以免大型依赖和后台任务拖慢“打开即读”的核心体验。

执行顺序固定为“来源与打开 → 导航与搜索 → 持续阅读 → Markdown → 轻量编辑 → Git → 差异化能力”。格式支持只作为能力域的输入，不单独以“新增语言数量”作为版本目标；新增格式必须同时补充识别、打开、搜索、高亮/渲染和回归样例。

阶段完成的判定采用双状态记录：

- **实现状态**：代码路径和自动化测试已具备。
- **验收状态**：在指定 Pixel_9 模拟器完成回归，并覆盖离线、异常恢复和大文件场景。

只有两种状态都满足时，才能把里程碑标记为“完成”并进入 Release；设备掉线或只完成定向测试时，路线图保留为“实现完成、验收待补”。

## 3. 产品原则

- 阅读优先：任何新增能力都不能以牺牲打开速度、滚动稳定性和可读性为代价。
- 离线优先：已导入的文件和项目在无网络状态下仍可继续阅读。
- 来源解耦：Local File、SAF、ZIP、Git Working Tree 和内置示例统一通过来源能力接口提供数据。
- 能力透明：明确显示来源是否可读、可写、可搜索、可刷新和可删除。
- 失败可恢复：网络失败、权限失效、编码异常、索引失败和文件消失都必须提供下一步操作。
- 小步发布：每个阶段形成可独立验证和发布的垂直切片，不把多个高风险能力绑定到同一版本。
